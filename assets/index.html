SAJS Library Site - Project Overview & System Documentation

Welcome to the official system documentation for the Seth M.R. Jaipuria School (SAJS) Library Site. This platform serves as a modern digital repository, discussion forum, and management system tailored to connect students, teachers, and administrators.

1. Executive Summary & Architecture

The SAJS Library Site is engineered as a highly responsive, secure, and modern Single Page-like application built on top of a serverless cloud infrastructure. The system leverages cloud resources to handle heavy assets, user state, real-time message sync, and auditing without requiring a dedicated server host.

Architecture Note: The client application communicates directly with Firebase cloud services (Auth, Firestore, Realtime Database, and Storage) securely via client SDK libraries, matching incoming requests against server-side Firestore Security Rules and Realtime Database rules.
[Web Client: HTML, CSS, JS] | +---> [Firebase Auth] (User Sign-in / OAuth) | +---> [Cloud Firestore] (Profiles, Books, Reviews, Audit Logs) | +---> [Firebase Realtime Database] (Real-time Forum Chat & Threads) | +---> [Firebase Cloud Storage] (PDFs, Book Covers, Profile Pictures)

Technology Stack & Rationale

Layer Technology Rationale
Frontend Core HTML5, CSS3, Vanilla ES6 JavaScript Minimizes initial page load times, eliminates framework overhead, and optimizes browser performance.
Design System Custom Glassmorphism Theme (Vanilla CSS) Employs custom HSL design tokens, CSS variables, flexbox/grid layouts, and micro-animations to deliver a unified, premium user experience.
Authentication Firebase Authentication Provides secure credential storage, OAuth (Google Sign-In), session handling, and tokens.
Structured Data Cloud Firestore A NoSQL document database that scales automatically. Used for indexed queries on books, user profiles, announcements, and audit logs.
Real-time Sync Firebase Realtime Database (RTDB) JSON database using WebSockets to synchronize chat messages and threads instantly with minimal network latency.
Asset Storage Firebase Cloud Storage Serves heavy digital files (book PDFs, cover images, user avatars) through Google's Global CDN with strict file size and type validation rules.

2. Authentication System & Dual-Login

The authentication system supports three native workflows: Standard Email Sign-In, Username Sign-In, and Google OAuth Sign-In.

User Entry -> Enter Credentials -> Click Login | v Check if entry has "@" character | +---> YES: Authenticate directly with Email and Password | +---> NO: Query Firestore users collection for Username match | v Email found? -> Authenticate with resolved Email and Password
  • Username / Email Sign-In: If the input field lacks an "@" symbol, the system assumes it is a username. It performs a Firestore query on the users collection matching the username field. Upon matching, it retrieves the user's registered email address and executes the secure Firebase Authentication call signInWithEmailAndPassword.
  • Teacher Registration Restriction: During signup, if a user attempts to select the "Teacher" role, the auth helper validates that their email matches the official school suffix _lko@jaipuria.edu.in. Students are unable to self-promote to moderator roles.
  • Profile Avatars: User profiles store an optional profilePicture URL from Firebase Storage. The app displays this image next to reviews, discussion posts, and in the navbar, falling back to dynamic name initials if no image exists.

3. Real-time Discussions Forum

The discussion forum acts as a real-time classroom communication hub. It features two sections: standard book discussions (tied to catalogued book IDs) and teacher-created custom discussion threads.

Senders List Modal

Teachers and administrators can view a clean list (👤) of all unique users who have posted in a specific discussion thread. This pulls from a cache of user profiles, displaying the member's profile picture, name, role, class details, or subject specialty.

Multi-Message Bulk Deletion

Moderators can click the Trash icon (🗑️) to enter bulk selection mode. Checkboxes appear next to each message in the feed. Once selected, clicking Delete Selected prompts the moderator for a deletion reason, removes all selected messages from the database, logs a MESSAGE_BULK_DELETE event in the audit trail, and exits selection mode.

Thread Deletion

Teachers and admins can delete entire discussions. Clicking the Delete Discussion button triggers a modal where they must type the exact title of the thread to confirm, alongside a reason. The thread metadata and all child messages are permanently removed, logging a DISCUSSION_DELETE action.

Student Actions

Students can hover over their own messages to display action buttons (✏️, 🗑️).

  • Edit: Inlines a text area and a mandatory "Reason for edit" field. Saving updates the database and logs a MESSAGE_EDIT audit log with the original and modified text.
  • Delete: Prompts for inline confirmation and a deletion reason. The message is deleted and logged under MESSAGE_DELETE with the deleted text.

4. Book Reviews & Ratings

Each book detail page includes a community review section.

  • Star Ratings: Users can leave a review accompanied by a rating from 1 to 5 stars.
  • Inline Reviews Editing / Deletion: Similar to the chat system, review owners can edit or delete their reviews inline. The edit window provides a text area and a reason input field. The delete action prompts the user for confirmation and a reason.
  • Moderator Actions: Teachers and admins can remove reviews directly. An inline panel prompts the moderator for a removal reason, deletes the review, and logs a REVIEW_MODERATE_DELETE event containing the deleted content.

5. Audit Logging & System Diagnostics

For accountability, the platform records every administrative and user-moderated action inside Firestore’s audit_logs collection.

Full Log Modal

Admins can view a detailed audit table inside the management tab. The Time column displays timestamps in a neat YYYY-MM-DD HH:MM format. The table includes a View Full Log action button for each entry, which opens a modal populated with:

  • Action Name & Category: (e.g., MESSAGE_BULK_DELETE, BOOK_EDIT, REVIEW_DELETE)
  • Metadata: Exact time, target ID, and the performer's name, email, role, and UID.
  • Reasoning: A mandatory text description written by the user/moderator explaining why the action was taken.
  • Content Comparisons:
    • For edits (Books, Reviews, Announcements, Messages), the modal displays side-by-side Before Edit and After Edit pre-formatted text boxes.
    • For deletions, it displays a Deleted Content block showing the removed content.

Reason for Action: "Inappropriate and non-constructive feedback."

6. Page-by-Page Feature Map

1. Home / Student Dashboard (index.html & student-dashboard.html)

For Students: A welcome dashboard showing checkout statistics, recommended books, active discussion threads, and school announcements. Allows students to edit their profile fields (favorite genre, bio, subjects, upload avatar).

For Teachers/Admins: Prompts quick redirects to the management dashboard.

2. Login Shell (login.html)

An auth page housing the Google login buttons and the email/username form. Features an independently scrollable form panel alongside a stationary brand container.

3. Library Catalogue (library.html)

Displays all books in a responsive grid. Users can filter books by genre chips (with an expandable "More" drawer) or type in a real-time search field (matches titles, authors, and catalog IDs).

4. Book Details (book-details.html)

Displays a book's overview: Title, Author, Year, Genre, Setting, Plot, Themes, Characters list, Conflict, Resolution, and Moral. Embeds the Digital Reader (a secure inline PDF viewer iframe).

5. Discussions Forum (discussions.html)

Features a split screen: the left column lists active threads (categorized by genres and custom discussions), and the right column loads the live chat area. Includes the teacher action bar and the message inputs.

6. Discover People (discover.html)

A grid of all registered users on the system, displaying cards with their names, roles, favorite genres, biographies, and avatars.

7. Library Management Dashboard (manage.html)

Accessible only to teachers and administrators. Features four tabs:

  1. Catalogue: Add/edit books (catalogue ID auto-increment, upload cover, upload PDF) and delete books.
  2. Library Schedule: Create, edit, and view classroom weekly activity schedules.
  3. Announcements: Post, edit, and delete school-wide news.
  4. Audit Logs: (Admin-only) The database monitoring log table with searching and detailed log viewers.

8. Guidelines (guidelines.html)

A static page showing the official library rules, book checkout limits, digital rights safety standards, and school behavioral guidelines.

7. Security Rules Overview

Firestore Security (firestore.rules)

  • Users: Read is public; creation validates the user fields and limits teacher role signup to official emails; updates freeze roles and UIDs.
  • Books / Schedules / Announcements: Read is public; writes are limited to isTeacherOrAdmin().
  • Reviews: Creation is limited to owner UIDs with valid rating values; updates are limited to owners; deletion is allowed by owners or moderators.
  • Audit Logs: Read is limited to isTeacherOrAdmin(); creation is open to signed-in users (must provide valid action and category fields); updates and deletions are entirely blocked (read-only/append-only logs).

Realtime Database Security (database.rules.json)

  • Messages: Reads and writes are open to authenticated users; validations ensure that new messages contain a sender, sender UID, timestamp, and message string.
  • Custom Threads: Reads and writes are open to authenticated users; validations check that all thread meta fields exist.

8. Conclusion & Future Roadmap

The SAJS Library Site provides a solid foundation for digital cataloguing and school collaboration. Future releases plan to introduce:

  1. AI Recommendation System: Integrate a recommendations system mapping user preferences (favorite genres/past checkouts) to catalogue items.
  2. Push Notifications: Web notifications alerting students when a discussion thread they participated in receives a new message.
  3. Weekly Quiz Tournaments: A built-in gamification engine letting teachers host weekly book-trivia quizzes with leaderboards to promote reading engagement.
